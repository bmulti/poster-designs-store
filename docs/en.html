About this application (16 languages)

[intro] # Poster Designs Store — what this application does Poster Designs Store is a catalogue and editor for reusable poster design instructions. Each design has a Number, a Name, and Instructions describing how an image or poster should be made. Designs are stored in MongoDB by default, while representative sample pictures are kept as ordinary image files in a separate samples directory. The program can browse, search, copy, add, edit, delete, import, export and back up the design records. It does not itself generate an image from a prompt. The usual workflow is to select a design in Poster Designs, inspect the sample images and copy its instructions for use in an image generator. Open Poster to change a design or attach a different sample image. Use Config to choose the MongoDB database, collections, directories and optional local posters.py fallback. File Browser provides separate image-file maintenance tools. UI Choices and Gateway are shared components and may be hidden when this application is embedded in another program. The source metadata identifies this program as Poster Designs Store, version 34, in project Image. The window title is Poster Store. Its configuration is stored in image_poster.json beside the Python source. By default, the MongoDB database is store and the poster collection is posters. Sample pictures, backups and exports are separate from MongoDB. Preserve both the database and those file folders when making backups. [tab:notes] # Notes Notes is the program's built-in help and navigation page. It explains the purpose of the poster catalogue and contains clickable headings to open the other tabs. It describes searching and copying designs, editing design records, adding sample pictures, cleaning image metadata, managing folders, and importing, exporting and backing up poster data. The built-in Notes page also explains the local posters.py fallback, the separate sample-image files and the confirmation steps used by deletion and other destructive operations. Its text is constructed inside the Python program rather than loaded from this external Notes file. Treat this English Notes file as a standalone description of the current controls; adding it does not alter the Python application's built-in page. [tab:poster-designs] # Poster Designs Poster Designs lists poster records with Number, Name and the opening portion of Instructions. The Number is the design's reference used when loading its sample image. Click a column heading to sort, and click again to reverse the order. Number sorting recognises numeric values and keeps numbered suffixes near their base numbers. The search-mode button alternates between Search Title and Search Inst. Search Title checks the number and name. Search Inst checks the full instructions. Multiple search words must all occur in the chosen text; comparison ignores letter case. X clears the search. Refresh reloads records from the selected data source. The shared Treeview also has HTML and CSV export buttons for the displayed list. Select a row to stage its details in the Poster editor. Copy places only the selected design's instructions on the clipboard. Auto Copy: On copies the instructions automatically whenever a row is selected; click the button to switch it off or on. Double-click a row to open the Poster tab with that design ready for editing. The previously selected design number is saved and restored when possible. The preview area displays sample pictures for the previous, current and next items, with the current picture larger than its neighbours. Prev and Next move through the available rows, wrapping at the ends. The preview uses files named after the poster number in the configured samples folder. If no matching image is available, that item has no displayed sample. [tab:poster] # Poster Poster is the editor for one poster design. Enter a unique Number and a Name, then enter or paste the full Instructions into the large text area. Add creates a new design. To revise an existing design, first open it from Poster Designs, change the fields and choose Update. When Update changes the design's number, the application also attempts to rename its existing sample image to the new number. It refuses a new number that already belongs to another loaded design. The Copy button beside Name copies just the Instructions. Copy to Clipboard copies Number, Name and the complete Instructions together. Backup writes the currently loaded designs to a dated JSON file in the configured poster backup directory. Delete requires a loaded design and asks for confirmation. Before deleting the record, it writes a dated JSON backup; if that backup fails, deletion is stopped. Database records and image files are separate, so do not assume that deleting a record also removes its sample picture from disk. The Poster Sample panel previews the image for the current number. Add a sample by dropping a PNG, JPEG, WebP or BMP image into Image File, or click the drop area to browse for a file. Paste Image from Clipboard imports an image copied to the clipboard when Pillow can read it. The Web Image URL field and Save Web Image Sample download a supported image from a supplied address. These methods save the image as <number>.png in the configured sample directory, rather than storing its pixels in the MongoDB design record. An existing PNG with that number may be replaced by a new sample. When loading an existing sample, the application checks matching JPEG files before PNG files. An older <number>.jpg or <number>.jpeg can therefore take precedence over a newly saved <number>.png. Check the samples directory if the preview seems not to show the latest picture. An image does not have to be present for its design instructions to be saved or copied. [tab:file-browser] # File Browser File Browser is a folder-based maintenance view, separate from the poster design catalogue. Enter or browse to a folder, use Up to move to its parent, Refresh to reload the current folder, or double-click a listed subdirectory to enter it. The left Treeview lists immediate subfolders, their direct-file counts, sizes and modified dates. The right Treeview lists files, sizes, modified dates and extensions. The footer summarises the current folder. Export buttons can save the displayed file list as HTML or CSV. Select one or more PNG or JPEG files to use Remove Metadata. The command recreates each selected file without its existing ancillary metadata. Clean + Copyright performs the same cleanup and adds the copyright notice entered in Config. That command requires a non-empty notice. Both commands request confirmation and then overwrite the selected original image files in place. They are not reversible from within the application. Make separate copies of important images before cleanup, particularly when they contain information that must be preserved. The browser accepts PNG, JPG and JPEG for these cleanup commands; it does not apply them to every image or document format displayed in the list. A status message reports the number of completed files and any errors. [tab:config] # Config Config holds the application-specific storage and data settings. Folder controls specify the image directory, poster root, poster samples, poster backups and poster exports. The initial poster folders are under posters_creator, with separate poster_samples, poster_backups and poster_exports subdirectories. Set these paths deliberately: the sample pictures are physical files, not embedded inside the database. Poster / MongoDB Data selects the data source and connection. The default source is MongoDB, using URI mongodb://127.0.0.1:27017/, database store and collection posters. The song collection field defaults to song_lyric for associated data functions. Refresh Poster Data reloads the current poster records. A posters.py path and a poster.py fallback choice are provided for reading and editing a local literal Python dataset. The program resets its source to MongoDB at startup; selecting the fallback does not itself migrate records between sources. Poster Data Import / Export provides Export, Import JSON / PY..., Repair Duplicate Numbers and Clear. Export writes Number, Name and Instructions from the loaded catalogue to a chosen JSON file. Import reads JSON or a Python file containing literal poster records; the Python source is parsed as data rather than executed. Records can use recognised alternative keys for number, title and instructions. Rows without a usable reference are skipped, and repeated references in the import file are collapsed, with the last occurrence taking precedence. Import operates on the configured MongoDB poster collection. It first writes a complete JSON backup of the existing collection, then inserts new poster numbers and updates matching numbers. Where imported numbers already have duplicate MongoDB documents, the import can remove the extra documents while retaining one. Import is not an append-only or non-destructive operation. Inspect the source file, database destination and backup directory before importing. Repair Duplicate Numbers first scans MongoDB and reports total documents, unique references, duplicate groups and unkeyed records. If duplicates exist, it asks for confirmation, writes a JSON backup, then removes extra documents sharing a normalised poster reference. Only one document is kept for each repaired reference; distinct data in removed duplicates may not be merged into the kept record. Keep the backup until the result has been independently checked. Clear asks for confirmation and exports the loaded poster records to a safety JSON file before attempting to delete all of them from the selected source. Clear is destructive and does not preserve the designs in that source after successful deletion. Verify that the safety file exists and is usable before treating the operation as recoverable. The separate samples folder is not a replacement for the saved instructions. The Image Metadata area contains the copyright notice used by File Browser when Clean + Copyright is selected. Managed Tags maintains a stored list of tag names. Add Tag saves a new name; Delete Selected Tag removes the selected name from that list but does not rename image files. Save Config writes application settings to image_poster.json. The selected tab, search options, last poster and appearance preferences are also retained when the application saves its state. [tab:ui-choices] # UI Choices UI Choices uses the shared interface component where available. It manages the application theme, display density and saved window size. If the shared component is missing, local fallback controls offer the same basic appearance settings and an Apply + Save action. The default theme is Graphite and the default density is Normal. The application retains the most recently used main tab and last selected poster. In embedded mode, the host program controls the overall window styling. The standalone preferences are still stored without changing the host's theme. UI Choices may not be displayed when the host disables that tab. [tab:gateway] # Gateway Gateway contains the shared Gateway Controller when enabled. It provides a launcher interface for registered applications and resources, with the available controls and stored entries determined by the shared Gateway module. Use it to open related tools without confusing launcher entries with the poster design records managed in this application. Gateway can be hidden in embedded mode when the host chooses not to show it. Its behaviour and storage are controlled by the shared module, not by Poster Designs Store's MongoDB poster collection.

Если его нет, локальные элементы предоставляют аналогичные базовые настройки и кнопку Apply + Save. Начальная тема — Graphite, плотность — Normal. Приложение запоминает последнюю главную вкладку и последний выбранный плакат. Во встроенном режиме общее оформление окна определяется программой-хозяином. Автономные настройки продолжают сохраняться, но не изменяют тему хозяина. Вкладка UI Choices может быть скрыта, если её отключила основная программа. [tab:gateway] # Шлюз Gateway содержит общий Gateway Controller, когда он включён. Это интерфейс запуска зарегистрированных приложений и ресурсов; доступные элементы управления и сохранённые пункты определяются общим модулем Gateway. Он позволяет открывать связанные инструменты, не путая записи средства запуска с дизайнами плакатов, которыми управляет приложение. Во встроенном режиме программа-хозяин может скрывать Gateway. Его поведение и хранение данных задаются общим модулем, а не коллекцией MongoDB Poster Designs Store.

[intro] # 海报设计资料库 — 本应用的用途 Poster Designs Store 是用于管理可重复使用的海报设计说明的资料库和编辑器。每个设计都有 Number（编号）、Name（名称）和 Instructions（制作图像或海报的说明）。设计记录默认存放在 MongoDB 中，代表性示例图片则作为普通图像文件保存在单独的样本文件夹内。程序可以浏览、搜索、复制、新增、编辑、删除、导入、导出及备份设计记录，但它本身不会根据提示词生成图像。 通常先在 Poster Designs 中选择设计，查看示例图片，再将其说明复制到图像生成工具中。通过 Poster 修改设计或关联其他示例图片。通过 Config 选择 MongoDB 数据库、集合、目录及可选的本地 posters.py 备用数据源。File Browser 提供独立的图像文件维护工具。UI Choices 和 Gateway 是共享组件；本程序嵌入其他应用时，这两个页面可能被隐藏。 源代码元数据表明，程序名称为 Poster Designs Store，版本 34，项目为 Image。窗口标题为 Poster Store。配置存储在 Python 源文件旁的 image_poster.json 中。默认 MongoDB 数据库是 store，海报集合是 posters。示例图片、备份和导出文件均独立于 MongoDB。备份时应同时保留数据库和这些文件夹。 [tab:notes] # 使用说明 Notes 是程序内置的帮助和导航页面。它说明海报资料库的用途，并提供可点击的标题以打开其他选项卡。内容涵盖设计的搜索与复制、记录编辑、添加示例图片、清理图像元数据、管理文件夹，以及导入、导出和备份海报数据。 内置 Notes 还介绍本地 posters.py 备用方案、单独存放的示例图片，以及删除和其他破坏性操作前的确认步骤。内置页面的文字直接在 Python 程序中构建，而不是从这份外部 Notes 文件读取。这份英语 Notes 文件仅独立描述现有控件；添加它不会改变程序内置页面。 [tab:poster-designs] # 海报设计列表 Poster Designs 列出各条设计记录的 Number、Name 以及 Instructions 的开头部分。Number 是载入相应示例图片时使用的编号。点击列标题可排序，再次点击可反转排序方向。编号排序能够识别数字，并让带数字后缀的项目靠近对应的基础编号。 搜索模式按钮在 Search Title 和 Search Inst 之间切换。Search Title 搜索编号和名称；Search Inst 搜索完整说明。输入的多个搜索词必须全部出现在所选文本中，且不区分大小写。X 清除搜索条件，Refresh 从当前选定的数据源重新加载记录。共享 Treeview 还提供把当前显示列表导出为 HTML 或 CSV 的按钮。 选中一行后，其数据会被载入 Poster 编辑器以备编辑。Copy 只将选中设计的 Instructions 复制到剪贴板。Auto Copy: On 会在每次选中一行时自动复制说明；点击按钮可以切换开关。双击某行可进入 Poster 选项卡并编辑该设计。程序会尽可能保存并恢复上次选中的设计编号。 预览区域同时显示上一条、当前条和下一条的示例图片，其中当前图片较大。Prev 和 Next 可循环浏览现有记录，到末尾后重新从开头继续。示例图片的文件名以海报编号命名，存放在配置的样本目录中。如果没有匹配的图片文件，该条记录就不会显示示例。 [tab:poster] # 海报编辑器 Poster 用于编辑一项海报设计。输入唯一的 Number 和 Name，再在大文本框中填写完整 Instructions。Add 新建设计。要修改已有设计，应先从 Poster Designs 打开该项，修改字段并选择 Update。如果 Update 改动编号，程序还会尝试将现有示例图片重命名为新编号。若新编号已属于另一条加载的设计，操作将被拒绝。 Name 旁边的 Copy 只复制 Instructions；Copy to Clipboard 则一起复制 Number、Name 和完整 Instructions。Backup 会将当前加载的设计写入配置的备份目录中带日期的 JSON 文件。Delete 需要先加载设计并确认。删除记录前会写入带日期的 JSON 备份；如果备份失败，删除就会停止。数据库记录与图片文件相互独立，因此删除记录不代表其示例图片也会从磁盘中删除。 Poster Sample 面板显示当前编号对应的示例图片。可将 PNG、JPEG、WebP 或 BMP 图片拖到 Image File 区域，或点击该区域浏览文件。若 Pillow 能够读取剪贴板中的图片，Paste Image from Clipboard 就能将其导入。通过 Web Image URL 和 Save Web Image Sample，可从提供的网址下载支持的图像。以上方法都把图片保存为样本目录中的 <number>.png，而不是把像素存入 MongoDB 记录。新样本可能替换具有相同编号的现有 PNG 文件。 载入示例图片时，程序先检查匹配的 JPEG 文件，再检查 PNG。因此，旧的 <number>.jpg 或 <number>.jpeg 可能优先于新保存的 <number>.png。如果预览没有显示最新图片，请检查样本目录。保存或复制设计说明并不要求必须有图片。 [tab:file-browser] # 文件浏览器 File Browser 用于文件夹维护，与海报设计资料库相互独立。输入或浏览选择文件夹；Up 进入上级目录，Refresh 重新加载当前目录，双击列出的子文件夹可进入其中。左侧 Treeview 显示直接子文件夹、其中直接包含的文件数量、大小和修改日期；右侧 Treeview 显示文件、大小、修改日期和扩展名。底部汇总当前目录的信息。可将显示的文件列表导出为 HTML 或 CSV。 选中一个或多个 PNG、JPEG 文件，可使用 Remove Metadata 将文件重建为不含原有附加元数据的版本。Clean + Copyright 执行相同的清理，并加入 Config 中输入的版权声明；该声明不能为空。这两个命令均需要确认，而且会直接覆盖原始图片文件。应用内无法撤销。清理前应另外备份重要图片，尤其是包含需要保留信息的文件。 这些清理命令支持 PNG、JPG 和 JPEG，但不适用于列表中的所有图像或文档格式。状态消息会报告完成的文件数量以及出现的错误。 [tab:config] # 配置 Config 包含本程序专用的数据和存储设置。文件夹控件可指定图像目录、海报根目录、海报样本目录、备份目录和导出目录。初始目录位于 posters_creator 下，分别设有 poster_samples、poster_backups 和 poster_exports 子目录。应仔细设置路径，因为样本图片是实际文件，而非嵌入数据库中的内容。 Poster / MongoDB Data 用于选择数据源和连接方式。默认来源是 MongoDB，URI 为 mongodb://127.0.0.1:27017/，数据库为 store，集合为 posters。相关数据功能使用的歌曲集合字段默认值是 song_lyric。Refresh Poster Data 重新加载海报记录。程序还提供 posters.py 路径及 poster.py 备用选项，用于读取、编辑本地由 Python 字面量定义的数据集。每次启动程序时，数据源会恢复为 MongoDB；选择备用方式不会在数据源之间迁移记录。 Poster Data Import / Export 提供 Export、Import JSON / PY...、Repair Duplicate Numbers 和 Clear。Export 把当前加载目录中的 Number、Name、Instructions 写入所选 JSON 文件。Import 可读取 JSON 或包含海报字面量记录的 Python 文件；对 Python 源文件只进行数据解析，不执行代码。可识别编号、标题和说明字段的其他合法键名。没有有效参考编号的记录会被跳过；导入文件出现重复编号时，以最后一次出现的记录为准。 Import 对当前配置的 MongoDB 海报集合执行操作。首先会对原有集合生成完整 JSON 备份，然后插入新编号的记录并更新匹配编号的记录。如果某导入编号已对应多个重复 MongoDB 文档，导入过程可能删除多余文档而只保留一条。这不是单纯追加或无破坏性操作。导入前请仔细核对源文件、目标数据库和备份目录。 Repair Duplicate Numbers 首先扫描 MongoDB，报告文档总数、唯一参考编号数、重复组及无编号记录。如果发现重复项，会请求确认，生成 JSON 备份，然后删除共享相同规范化海报编号的多余文档。每个修复的编号仅保留一个文档；被删除重复项中的不同数据可能不会合并到保留的文档。独立核实结果之前请保留备份。 Clear 要求确认，并在尝试删除选定数据源中的所有已加载设计前，将它们导出到安全 JSON 文件。此操作具有破坏性：删除成功后，设计不再存在于该数据源。只有确认安全文件存在且可用，才能将操作视为可恢复。单独的样本图片目录不能替代已保存的设计说明。 Image Metadata 区域存放 File Browser 在 Clean + Copyright 时使用的版权声明。Managed Tags 管理已保存的标签名称列表。Add Tag 添加名称；Delete Selected Tag 将选中名称从列表移除，但不重命名图片文件。Save Config 把应用设置保存到 image_poster.json。保存程序状态时，还会保留当前选项卡、搜索选项、上次选择的海报和外观偏好。 [tab:ui-choices] # 界面选项 UI Choices 在共享组件可用时使用该组件管理主题、显示密度和已保存的窗口尺寸。如果共享组件缺失，本地替代控件提供相同的基本选项和 Apply + Save 操作。默认主题是 Graphite，默认密度是 Normal。程序会记住最近使用的主选项卡和上次选中的海报。 嵌入其他程序时，由宿主程序决定整体窗口样式。独立运行的外观偏好仍会保存，但不会更改宿主程序的主题。如果宿主禁用了该选项卡，UI Choices 可能不显示。 [tab:gateway] # Gateway 启动入口 启用时，Gateway 会显示共享的 Gateway Controller，为已注册的应用和资源提供启动界面。具体控件和保存的条目由共享 Gateway 模块决定。它用于打开相关工具，不能将启动器条目与本程序管理的海报设计记录混淆。 嵌入模式下，宿主程序可以隐藏 Gateway。它的行为和数据存储由共享模块控制，而不由 Poster Designs Store 的 MongoDB 海报集合控制。
